## Product Constitution v1 candidate — 2026-08-26

A new doctrine candidate consolidates the current Product boundary, attention, closure, and autonomy reasoning.

It does **not** supersede `PRODUCT.md` yet. Promotion requires explicit reconciliation/full acceptance audit against current Product, Responsibility, design, implementation, and live discovery contracts.

### Candidate purpose hierarchy

```text
WHY
Cognitive freedom / stop carrying unresolved communication in working memory

VALUE
Attention Delegation

MANAGED OBJECT
Email-originated/evidenced Open Coordination Loop

DOMAIN
Outcome + Responsibilities + Expected Events + Evidence + Return Triggers + Closure Criteria + Authority/Uncertainty

PROJECTION
Needs You / Waiting / Later / Review / Done

INTERACTION
Moment = minimum context restoration when attention returns
```

### Candidate jurisdiction

Lunowa is strongest when unresolved work is:

- materially communication-originated/evidenced;
- externally/interpersonally dependent;
- temporally open;
- state/event driven rather than a simple timestamp reminder;
- costly enough to monitor manually;
- not already better owned by a structured system of record.

Use three ownership modes:

1. **Primary Steward** — Lunowa carries monitoring where no stronger system owns the heterogeneous state.
2. **Overlay / Monitor** — CRM/ticket/project/domain system remains canonical; Lunowa only closes a communication-attention gap.
3. **Out / Reference only** — generic tasks, project plans, CRM pipelines, support-ticket lifecycle, deterministic workflow automation, generic knowledge storage, or other domain systems already solve the state problem.

Anti-scope candidate:

> Lunowa does not become a Task Manager, Project Manager, CRM, ticket system, workflow engine, or domain system of record merely because related communication appears in email.

## Attention doctrine candidate

Separate four questions:

1. **Operational State** — what changed?
2. **Attention Need** — does the user now need to know/decide/act?
3. **Delivery Urgency** — when should that attention interrupt?
4. **Authority** — may Lunowa decide/act without human approval?

Do not collapse these into one priority/confidence score.

A new message/reply is evidence, not automatically an attention event.

Candidate delivery hierarchy:

- Silent;
- Passive / Needs You;
- Deferred or opportune/batched;
- Immediate.

Directional principle:

> **Not as soon as possible. As late as safely possible.**

The exact policy/thresholds remain hypotheses.

## Closure doctrine candidate

Current candidate semantics:

```text
action performed
!= completion claimed
!= outcome satisfied
!= monitoring closed
```

A reply/completion claim is evidence, not closure.

Automatic closure should normally require relevant:

- Outcome gate;
- Obligation gate;
- Evidence gate;
- Authority gate.

Silence alone must not be treated as proof of satisfaction.

Candidate internal terminal dispositions include:

- Satisfied;
- Cancelled / Waived;
- Superseded;
- Expired;
- Abandoned.

A violated/missed promise normally creates renewed attention rather than automatic loop closure.

Outcome disposition and monitoring state are separate: `Satisfied != Closed`.

Closure must preserve history and allow later contradictory evidence to reactivate monitoring without rewriting source history.

## Autonomy doctrine candidate

Strongest current principle:

> **Attention delegation first; authority delegation only through explicit bounded policy.**

And:

> **Capability != permission.**

Allowed autonomy is an action/context/scope decision, not a global `AI autonomy = high` setting.

### Candidate default responsibility split

**Lunowa may autonomously, within authorized scope:**

- observe source evidence;
- derive candidate interpretations;
- reconcile permitted low-risk internal monitored state through trusted rules;
- monitor time/event conditions;
- surface/restore context;
- prepare summaries/drafts/next actions.

**User authority by default for:**

- external email sending;
- shared-system/calendar changes involving others;
- statements/commitments made on the user's behalf;
- ambiguous or material judgment.

**Outside initial autonomous authority / explicit higher-risk transaction boundary:**

- money movement;
- contract acceptance;
- destructive/poorly reversible deletion;
- security/permission changes;
- similarly consequential identity-sensitive actions.

Security/authority candidate:

```text
LLM proposes
-> deterministic authorization/policy mediates
-> human approval where required
-> tool executes
-> result is reconciled/verified
```

The LLM does not decide its own permission and does not become canonical truth merely by inference.

Human approval should protect material authority boundaries, not every harmless internal update; otherwise Review/approval becomes a second inbox and defeats Attention Delegation.

## Current external evidence relevant to this candidate

The dated evidence artifact records exact sources and limitations. High-value findings include:

- 2025/2026 autonomy frameworks explicitly separate technical capability from allowed autonomy;
- Microsoft 2026 agent governance scales oversight with risk and treats assist-to-execute as a major boundary;
- NIST 2026 work treats agent identity/authorization/security/TEVV as active standards problems;
- OWASP 2026 treats excessive agency/tool misuse/identity privilege as first-class agentic risks and recommends least privilege/complete mediation;
- current Microsoft Cowork can run event-driven monitoring but defaults shared actions such as email send/post/system changes to draft-and-approve, while allowing bounded session/action/recipient pre-authorization;
- ClawsBench and ClawMark show substantial remaining long-horizon/safety limitations in benchmarked productivity-agent settings; do not convert their percentages into Lunowa production estimates;
- current agent-verifier research reinforces `process/action != verified outcome`;
- human delegation studies show users do not perfectly calibrate when to delegate or adopt AI output.
